# PluginHub 插件开发

先读取当前仓库的 AGENTS.md 和目标功能已有实现。需要接入入口与具体示例时，读取[实现参考](references/implementation.md)。文中源码路径相对于仓库根目录。

## 需求与设计

从使用场景确定展示信息、输入、操作、刷新、启停、睡眠和重启行为。用户要求采访时逐项确认影响实现的选择，保留已确定的决策。可逆的小选择可以自行确定，在交付时说明。

将确认结果记录到 docs/ 下对应设计文档，并在 docs/README.md 和主设计文档添加入口。更新旧设计时消除冲突，标明已确认需求、实现选择和待验收项。用户只要求设计时完成设计，授权实现后继续实现和验证。

## 实现选择

- 查询或定时采样且现有 Component 能表达内容时，使用 Resources/BundledPlugins/ 下的 Python 插件。
- 即时输入、持续动画、自定义卡片或独立生命周期，参考 Countdown.swift 和 NetworkUsage.swift 的原生实现。
- 复用现有模型和渲染器。新增 Component case 时同步更新编码、解码和渲染分发。

## 管理与卡片

插件进入「设置 → 插件」列表，行内开关控制启用，选中后在右侧编辑配置，沿用保存和重置。采集设置放入插件详情。启停行为按用户确认的生命周期实现。

设计功率流向和类似监测卡片时，读取[监测卡片设计参考](references/monitoring-ui.md)，沿用用户确认的信息层次与动效方向。

Dashboard 按配置的启用状态和排序显示卡片。布局由内容决定，用户要求单页时在同一卡片展示。沿用现有底色和圆角，动态列表需要固定高度时预留最大行数空间。处理等待、空数据、失败和手动刷新重试。

遵守 Swift 6 并发约束。阻塞执行在后台运行，主 actor 更新界面。定时与手动操作重叠、停用后旧请求返回时，保持累计和状态一致。

持久化按插件实例隔离，复用 stateID 和项目应用支持目录。Swift JSON 使用 PluginHubJSON 编解码与原子写入。时间驱动功能保存结束时刻，根据当前时间恢复进度。高频界面刷新放在 UI 层，按状态变化保存数据。

## 验证与交付

按改动验证正常入口、输入边界、失败和恢复。Python stdout 应能解码为 PluginOutput。外部接口可用模拟响应检查解析，真实账户调用符合用户授权。

运行 swift build，用 bash scripts/dev-app.sh 生成开发版。当前测试是手动 runTests()，swift test 的无用例结果不能作为功能验收通过依据。对计数差分、时间计算、持久化等按需运行隔离检查。

UI 改动尽量渲染预览或运行应用查看。说明构建、预览和实际交互各自的验证结果，提供开发版 App 绝对路径，提醒退出旧实例后打开。用户要求发布安装包时读取打包脚本，核对版本、架构、签名及 DMG 内容。提交、推送和发布依据用户授权。
